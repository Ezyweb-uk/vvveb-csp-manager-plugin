Sets one Content-Security-Policy header per page, merged with whatever any other plugin (e.g. a payment gateway plugin) has already queued for that same request. Exactly one profile applies per request: the "Checkout policy" below for any route listed in "Checkout routes", the "Default policy" for everything else.

Report-only sends Content-Security-Policy-Report-Only — nothing is blocked, but violations are still logged to "Report URI" below, so you can see what WOULD be blocked before switching to Enforce.
Where the browser sends violation reports. Leave as /csp-manager-report (this plugin's own endpoint, logged via error_log()) unless you have your own collector.
Space- or comma-separated route "module" values (as Routes::getUrlData()['module'] reports them) that get the strict Checkout policy below. Everything else gets the Default policy.
Rewrites a handful of known onclick="..." attributes the storefront theme ships (password show/hide, login/guest toggle, shipping-address toggle) out of every storefront page's final HTML, so they stop tripping the script-src-attr CSP directive. Works even for markup copied in via a page's data-v-copy-from/ data-v-save-global (e.g. the shared header), since it runs on the fully-resolved HTML, not any one template file. Only turn this on if your theme has its own click listeners for these controls (in an external script file): it removes the onclick attributes, so on the stock Landing theme the password eye, login/register and shipping-address toggles stop working. Off by default. The PayPal Smart Buttons plugin's checkout script keeps the Landing checkout working when its inline code is blocked.
Belt-and-braces: removes the Cookie Notice plugin's #cookie-notice banner, its scripts and style (#cookie-notice-js, #cookie-notice-config, #cookie-notice-consent-default, #cookie-notice-style) and the #cookie-notice-revisit button (Vvveb 1.0.9.0 plugin) from the checkout page's final HTML, in addition to (not instead of) that plugin's own checkout-skip fix. Protects you if that plugin is ever reverted, not updated, or replaced with a different cookie-consent plugin that doesn't skip checkout itself. Only touches routes listed in "Checkout routes" above, and only recognizes that specific plugin's element ids.
Theme widgets and third-party scripts to take out of the checkout page, one per line, instead of allowing their hosts in the strict checkout policy (a payment page should load as little third-party code as possible). They still show on every other page. #some-id removes the element with that id; .some-class removes every element with that class, including what is inside it; anything else is matched against the src or href of script, img, iframe, link, source, embed and object tags (for example a host name). Only touches routes listed in "Checkout routes".
Optional. A developer/admin address to email a summary of a CSP violation report to, in addition to the existing PHP error log entry. Leave blank to disable.
